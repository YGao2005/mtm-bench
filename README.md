# MtM-Bench — Measuring the Measurers

A **meta-evaluation benchmark for agent-failure detectors**: it grades the *graders* of agent
transcripts. Drop a no-LLM keyword baseline, a deterministic compiled check, and any number of LLM
judges onto **one ruler** and compare them with the **two-numbers discipline** — never a single
pooled score.

Companion artifact to the paper *"Measuring the Measurers: Grading Agent-Failure Detectors, and
Knowing When a Benchmark Cannot."* Every number in the paper's τ²/census sections reproduces
**offline** from the data shipped in this repo with one command.

## Why two numbers, never pooled

A single accuracy/F1 hides the failure mode that matters. A judge can score well by flagging
everything (high recall, ruinous false-alarm rate) or by flagging nothing. So every cell reports
**both** numbers side by side with Wilson CIs:

- **recall-on-corrupt** — of the traces that are *actually* bad (the oracle said SUCCESS but a
  human/independent mechanism says a policy was violated), how many the detector flags. ↑ better.
- **fire-on-clean** — of the genuinely-clean traces, how many it *wrongly* flags. ↓ better.

There is deliberately no `f1` on any report type. A contestant sitting on the
`recall ≈ fire-on-clean` diagonal has no separating signal, however high its recall — the ruler is
built to make that visible.

## The firewall (the rule you must not break)

Your detector sees the **trace only** — never the gold label, reference trajectory, or any
answer-key field. Reading the answer key to "catch" a failure is *oracle-copying*: it rebuilds an
inferior copy of the oracle and destroys the disagreement the benchmark measures. The `GoldStore`
enforces this structurally (gold lives in a sidecar the trace never carries; `find_leaks` audits
residual answer-key fields). In the paper's ablation, letting a judge see the gold inflates its
balanced accuracy from 65% to 100% — that gap is *why* the firewall is load-bearing. If your
contestant's predicate *is* the gold mechanism, declare it via `tautological_on=` so its number is
flagged "by construction," never touted as a win.

## Install

```bash
pip install -e .            # only dependency: pydantic
```

## Quickstart

```python
from mtm_bench import GoldItem, detector_entry, score_leaderboard, load_tau2_results

# score a custom detector on the shipped τ² human-census cell — see scripts/reproduce_paper.py
report = score_leaderboard(gold_items, traces, [my_entry])
print(report.render())                 # text table, both numbers + Wilson CIs
open("out.json", "w").write(report.to_json())   # JSON-safe (nan → null)
```

Reproduce the paper's numbers (offline, no API keys):

```bash
python scripts/reproduce_paper.py            # census scorecard, truth-clean decomposition, FP-gap, over-flag
```

The APB process-judgment leaderboard additionally needs a clone of
[AgentProcessBench](https://github.com/RUCBM/AgentProcessBench) (their gold + released predictions
are not redistributed here — see `data/external/`):

```bash
mtm-bench apb-leaderboard --apb-dir /path/to/agentprocessbench --json
```

## Submit a detector

Three axes, one contestant protocol each — see [docs/SUBMIT.md](docs/SUBMIT.md) for worked examples:

| Axis | What it decides | Callable signature | Scorer |
|---|---|---|---|
| **Outcome** | is this SUCCESS trace a corrupt success? | `predict(trace, spec) -> bool` | `score_leaderboard` |
| **Process-quality** | per step: harmful / neutral / helpful | `grader(trace) -> dict[span_id, -1\|0\|1]` | `score_pq_entries` |
| **Attribution** | which step is the critical failure? | `localize(trace) -> span_id \| None` | `score_attribution` |

## Dev/test split

The eval manifest (`data/tau2/eval_manifest.json`) encodes a **frozen, task_id-keyed split** that
is model-invariant — the same 26 airline / 58 retail held-out task IDs apply to every model's
rollout. Tune on `dev`, report on `test`:

```bash
python -m mtm_bench splits                              # show the split table
python -m mtm_bench tau2-leaderboard --split test ...   # score only held-out tasks (default)
python -m mtm_bench tau2-leaderboard --split dev ...    # score only dev tasks
python -m mtm_bench tau2-leaderboard --split all ...    # ignore the split
```

The split algorithm is `sha1(task_id)` stratified alternation — every trial of a given task lands
on the same side, so no task appears in both dev and test.
